# コーディング規約 (Coding Standards & Documentation Policy)

本プロジェクト（RogueLabyrinth）におけるTypeScript/JavaScriptコードのコーディング規約およびTypeDoc/JSDocドキュメント記述規約を定めます。

---

## 1. 変数・プロパティ・定数の TypeDoc / JSDoc 記述規約

すべてのクラスプロパティ、インターフェース/型のフィールド、モジュールレベルの変数および定数には、**ヌケモレなく必ずTypeDoc（JSDoc `/** ... */`）形式の詳細コメントを記述**します。

### 1.1. 基本ルール
1. **変数・プロパティの役割説明**:
   - その変数が何のために存在し、どのシステム（ゲームエンジン、描画、UI、オーディオ等）でどのように参照・更新されるかを明記する。
2. **型と単位の明記**:
   - 数値型の場合は、単位（ミリ秒、セル数、ターン数、パーセンテージ、ゴールド数等）や許容範囲（0以上、正負等）を記載する。
3. **初期値の明記**:
   - インスタンス生成時や初期化時にどのような初期値がセットされるかを `@default` または `- 初期値: ...` として明記する。

## 2. フラグ値（boolean / 状態値 / Unionリテラル）の特別記述ルール

フラグ値（`isAlive`, `isShopItem`, `isThiefMode` 等の真偽値や、状態を表す文字列Union・Enum）は、プログラムの挙動を左右する極めて重要な値です。そのため、以下の4項目を必ずコメント内に網羅します。

### 必須記載項目
1. **フラグの概要**: 何の状態・権利・フラグであるか
2. **想定値とその意味（バリエーション一覧）**:
   - `true`: どのような状態か、何が許可・実行されるか
   - `false`: どのような状態か、何が禁止・通常動作となるか
   - （Union値の場合）取り得るすべてのリテラル文字列とそれぞれの状態説明
3. **初期値**: ゲーム開始時・オブジェクト生成時のデフォルト値（例: `false`, `true`, `undefined`）
4. **状態変化の契機**: どの処理・イベントによって値が切り替わるか

### 記述例（boolean フラグ）
```typescript
/**
 * ショップの未会計商品フラグ。
 * - 想定値:
 *   - `true`: 店主の店内に陳列されている未会計商品（部屋から持ち出すと泥棒判定が発動）
 *   - `false`: プレイヤーが代金を支払って購入済み、または通常のフロア床落ちアイテム
 * - 初期値: `false`（ショップ部屋生成時に配置されたアイテムのみ `true`）
 * - 変化契機: 店主への会計（TALK / 金貨精算）時に `false` へ解除
 */
isShopItem?: boolean;
```

### 記述例（状態Union / 段階フラグ）
```typescript
/**
 * 遠隔攻撃の属性種別。
 * - 想定値:
 *   - `'magic'`: 魔法弾攻撃（壁や障害物を貫通せず、着弾時に青白い光線エフェクトと被弾SEが発生）
 *   - `'fire'`: 火炎ブレス攻撃（炎エフェクトと爆発SEが発生、可燃物を破壊）
 *   - `undefined`: 遠隔攻撃を持たない近接専用モンスター
 * - 初期値: モンスター定義（MONSTER_DEFS）で指定、通常モンスターは `undefined`
 */
rangedAttackType?: 'magic' | 'fire';
```

## 3. クラスメンバ（public / protected / private）の網羅方針

- 外部から呼び出される `public` メソッド・プロパティはもちろんのこと、内部で状態を保持する `private` / `protected` なメンバ変数、タイマーID、フラグ、キャッシュ変数に至るまで、漏れなくすべてTypeDocコメントを付与します。
- `typedoc.json` において `"excludePrivate": false` を有効化し、内部アーキテクチャまで正確に自動生成APIリファレンス（`docs/api/`）に反映させます。

---

## 4. 自動生成ドキュメントの運用フロー

1. コード内の変数・関数・クラスにTypeDocコメントを記述・更新する。
2. `npm run doc` を実行し、`docs/api` ディレクトリにHTMLドキュメントを再生成する。
3. `npm run build` を実行し、TypeScriptの型チェックおよびViteビルドがエラー0で通過することを確認する。
4. Gitコミットに含めてバージョン管理する。
